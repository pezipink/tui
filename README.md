# Tui

Documentation: [docs/architecture.md](docs/architecture.md) explains how the compiler works, [docs/captures.md](docs/captures.md) covers closure captures, and [AGENTS.md](AGENTS.md) is the guide for agents working in this repository.

Tui is a tiny prototype .NET language built on [Rangi](https://github.com/pezipink/rangi). It shows the two ways a Racket `#lang` can use Rangi:

* **At phase 1, as a type system.** While the macro expander expands a Tui module, the language reads the referenced assemblies (mscorlib and anything named with `using`) with Rangi's lazy CLI metadata reader. It uses them to resolve type names, find methods and overloads, and report type errors at expansion time, so DrRacket shows them as you edit. Hovering over an expression or binding in an editor running racket-langserver shows its type, including the resolved parameters of generic types such as `List<int32>`. The hover is checked through racket-langserver, not in the DrRacket GUI, where the `<` and `>` of generic types appear escaped as `\<` and `\>`.
* **At phase 0, as a back end.** Each Tui expression expands to typed IL. The module collects its methods into a Rangi ilasm program, which Rangi assembles into a Windows PE image and runs on the .NET Framework CLR.

Tui uses the s-expression reader, so there is no parser.

## Requirements

* Windows with the .NET Framework 4.x and the v4.7.1 reference assemblies (`C:\Program Files (x86)\Reference Assemblies\Microsoft\Framework\.NETFramework\v4.7.1\`).
* Racket 8.16 CS.
* Rangi installed as the `rangi` package, for example `raco pkg install --link --name rangi c:\repos\rangi`.

Install Tui itself with `raco pkg install --link --name tui c:\repos\tui`.

## The language

```racket
#lang tui
(using "System")                ; reference an assembly by name or by path
(open System.Text)              ; search a namespace for short type names

(define (fact [n : int]) : int
  (if (< n 2) 1 (* n (fact (- n 1)))))

(define-syntax-rule (unless c body ...) (if c (begin) (begin body ...)))

(Console.WriteLine (fact 10))                   ; static call: Type.Method
(Console.WriteLine (.ToUpper "kia ora"))        ; instance call: .Method receiver args
(let ([sb (new StringBuilder)])
  (.Append sb "ab")
  (sb.Append "cd")                              ; instance call on a local: a.Method args
  (Console.WriteLine (.ToString sb))
  (Console.WriteLine sb.Length))                ; property read: a.Name, falls back to get_Name
```

* Types: `int`/`int32`, `long`/`int64`, `double`/`float64`, `bool`, `char`, `string`, `object`, `void`, and any public .NET class by name.
* Forms: `define`, `let`, `set!`, `begin`, `if`, `while`, `and`, `or`, `not`, `new`, `list-of`, `fn`, `null`, `null-of`, `null?`, the arithmetic operators `+ - * / %` (`+` also joins strings), the comparisons `< > <= >=`, and `=`.
* A `define` may leave out its return type. The type is then taken from the body's last expression, so `(define (square [x : int]) (* x x))` returns `int`. A recursive `define` must write its return type, and so must a body whose last expression is a bare `null` or `fn`. A module `define` may also leave out its type: `(define total (square 3))` takes its type from the expression.
* `null` is the null reference. A bare `null` takes its type from where it is used: the parameter of a fn or .NET method or constructor it is passed to (`(String.IsNullOrEmpty null)`, `(new System.Text.StringBuilder null)`), the other side of `=`, or the declared return type of a `define`. Where nothing says what reference type it is, it is an error: `(let ([x null]) x)`, and `(Console.WriteLine null)`, which more than one overload accepts. `(null-of T)` is a null of the reference type `T` (a type name, as in `default-of`), for places with no expected type: `(let ([s (null-of string)]) (set! s "x"))`. A value type (`int32`, `int64`, `float64`, `bool`, `char`) cannot be null. `(null? e)` is `true` when the reference `e` is null, and `(= e null)` does the same.
* `(list-of e ...)` builds a `System.Collections.Generic.List<T>`. T is the type of the first element and every other element must convert to it. `(list-of 1 "a")` is a type error. An empty list needs `(new System.Collections.Generic.List<T>)`.
* Arrays: a type is written with pipes, `|int32[]|` or `|string[][]|` for a jagged array. `(array T e ...)` builds an array from its elements, and `(new-array T n)` builds one of length n with default elements. `(aref a i)` reads an element and `(set! (aref a i) v)` writes one. `a.Length` reads the length. `(for-each [x xs] body ...)` loops over an array, a `List<T>` or any `IEnumerable<T>`, or a string, and `[x : T xs]` checks the element type. An array converts to `IEnumerable<T>`, so `(Enumerable.Contains a 3)` works with `using System.Core`. Multi-dimensional arrays, pointers and byrefs are not supported.
* Static fields and enums: `Type.Name` reads a public static field, so `System.Int32.MaxValue`, `Math.PI` and enum members such as `System.DayOfWeek.Monday` work as values. Enums can be passed, returned, stored and compared with `=`, but Tui cannot define one. `examples/arrays.rkt` and `examples/enums.rkt` show these.
* `(fn DELEGATE (param ...) body ...)` builds a delegate instance, such as `Action<T>`, `Func<...>` or `Predicate<T>`. DELEGATE is written in full, or may be left out in four cases: when the `fn` is in a position that expects a delegate (for example the tail of a `define` whose return type is a delegate); when it is a bare argument of a .NET method or constructor (the overload supplies the delegate type, so `(.ForEach xs (fn (x) (Console.WriteLine x)))` works, and a generic method's type arguments that only the `fn` mentions are fixed by its body, as in `(Enumerable.Sum (Enumerable.Select xs (fn (x) (* x 2))))`); when every parameter is annotated, as in `(fn ([x : int]) (= (% x 2) 0))`, and the delegate is `Func` or `Action` of the body's type; or when an unannotated parameter is an argument of a call in the body whose name has exactly one overload, as in `(fn (s) (String.IsNullOrEmpty s))`. The parameter and return types come from the delegate's `Invoke` method. The arity must match and the body must produce the return type. Multi-argument generics need pipes because the reader splits `Func<int32,int32>` at the comma, so write `|Func<int32, int32>|`. Each lambda becomes a generated class with one field per captured cell and an `Invoke` method. The value is a delegate over `Invoke` on an instance of that class. Lambdas are first-class objects: they can be stored, passed, returned and called, as `(f x)` or as `(.Invoke f x)`. A lambda can use the locals and arguments of the enclosing method, and of any enclosing lambda. A capture is shared, not copied: `set!` in the lambda is seen by the method and by other lambdas that capture the same variable. Each run of a `let` makes new variables, so a lambda in a loop body captures its own copy. Captures are stored in cells (a one-element array per variable), and the cell is copied into the class field when the lambda is created. The compiler decides which names are captured with two expansion passes. The first pass expands the method and records the variables that lambdas read. The second pass expands it again with those variables as cells. So a name a macro introduces into a lambda is captured like any other name. Methods with lambdas are expanded twice, so expansion must be deterministic. See [architecture.md](docs/architecture.md) sections 6 and 10 for how types are inferred.
* Overloads are resolved at expansion time. The implicit conversions are widening (int32 to int64, integers to float64), boxing to `object`, and reference upcasts to a base class or interface (no IL is emitted). An upcast costs less than a conversion to `object`, so `List<string>` picks `IEnumerable<string>` over `object`. Generic methods may omit their type arguments, e.g. `(Enumerable.Where xs even?)`, and the type arguments are inferred from the argument types. Explicit type arguments such as `Enumerable.Where<int32>` are still accepted and are used as given. A `_` stands for an argument to infer, and a list may end early: `(Enumerable.Count<_> xs)` and `(|Enumerable.Select<int32, _>| evens square)` both work. Inference only applies when a parameter's type is exactly the method's type variable, with no unification. Names with commas need pipes, e.g. `|Enumerable.Select<int32, int32>|`.
* A `fn` value can be passed as an argument and stored with `let`, like any other value.
* Module-level values: `(define name : type expr)` declares a static field on the module class. The type annotation is required. Each value gets a static initializer method, and the entry point runs the initializers in source order before the body. A function may read any module value. An initializer may read only the values defined before it: a direct read of a later value is a syntax error (`module value used before it is defined`). A read through a function call is not checked. A lambda that reads a module value needs no capture, because the value is a static field, and it sees the current value. `set!` on a module value writes the field. Module values can only be defined in a module, not in a REPL interaction. `examples/values.rkt` shows this.
* Records: `(record Name [field : type] ...)` declares a sealed class with a constructor that takes every field in order, a private field per name, and a `get_name` and `set_name` property. `p.name` reads a field, `(set! p.name e)` and `(p.set_name e)` write it, and `(new Name e ...)` builds one. Like module values, a record is declared in a module, not in a function or a REPL interaction, and a later record can use an earlier one. A field cannot be `void` or repeat a name, and a record name can be declared only once in a module. Its descriptor is added to the type environment while the module expands, so the type checker sees it before the IL is built. `examples/records.rkt` shows this. Type-syntax-classes can name a record too: `(define-type-syntax-class pointType Point)` or `(has (.get_x () : int32) (.get_y () : int32))` match a `Point` by name or by shape, and `examples/records.rkt` uses them in `type-matches?` and `type-match`.* Macros are hygienic. `define-syntax-rule` is the simple form. `define-syntax-parser` (from `syntax/parse/define`) can ask the type checker about an argument and read the CLR metadata behind it. `examples/lists.rkt` has `sum-of`, which reads the element type from the closed `List<T>`'s `get_Item` return type, and raises a syntax error for element types it does not support. `examples/types.rkt` has `default-of`, which takes a type name: it expands to a literal for `int32`, `bool`, `float64` and `string`, or to `(new T)` for a class with a public parameterless constructor, and is a syntax error otherwise. `type-name-of` expands to the Tui name of its argument's type as a string literal; the argument is type checked but not evaluated. `(typeof T)` is the run-time `System.Type` of the type name `T`, as in C#: it emits `ldtoken` and `Type.GetTypeFromHandle`, so it works for primitives, classes without type arguments and local records (`(.get_FullName (typeof System.Text.StringBuilder))`). It is a syntax error for `void`, and for generic instances and arrays, which Rangi's `ldtoken` cannot yet encode. The phase-1 helpers `tui-type-of`, `tui-member-return-type`, `tui-resolve-type`, `tui-has-default-ctor?`, `tui-type->string` and `class-of` are exported `for-syntax`. `tui-static-overloads` and `tui-instance-overloads` list the overloads of a method name as type signatures, and `tui-member-names` lists a type's public method names. `supertypes` gives the transitive base classes and interfaces of a type. These only cover members whose signatures use types Tui models, so the overload counts are smaller than the full .NET counts. `examples/phase1.rkt` uses them.
* Other phase-1 definitions pass through to the module unchanged: `define-syntax-class`, `define-splicing-syntax-class`, `define-simple-macro`, `begin-for-syntax`, `define-for-syntax` and `define-syntaxes`. As in Racket, a syntax class that a macro uses must be defined inside `begin-for-syntax`. `examples/syntax-classes.rkt` shows them. The `threading` package works too: `~>` and `~>>` expand to ordinary applications and are type checked like any other call (`examples/threading.rkt`). A bare `.Name` clause reads a property or calls a zero-argument method, so `(~> "  tui  " (.Trim) .Length)` is 3. `~>>` puts the threaded value last, so instance methods need `~>`. Its binding forms (`as~>`, `cond~>`, `and~>`, `some~>`, `lambda~>`) are not supported. They expand to Racket `let`, `cond` or `lambda`, which the type checker rejects, and `as~>` reports `unbound function`.
* Syntax classes give macros the types of their arguments without calling those helpers. `typedExpr` matches any expression and has `x.Type`, the type the checker gives it. `typeName` matches an identifier naming a type and has `x.Type`. Richer constraints are written with `define-type-syntax-class`, using a pattern language of generics, members, named patterns and combinators: `examples/lists.rkt` builds `typedList` from it, and `examples/type-patterns.rkt` shows nested and complex cases. `type-match` and `type-matches?` test the same patterns at phase 1. The grammar is in `docs/architecture.md`, section 12.1. Dot attributes are read in templates as `x.Type` and elsewhere as `(attribute x.Type)`. The classes live in a `begin-for-syntax` beside the helpers they call, because their attribute expressions run at phase 1.
* Partly done: the checker stamps each expanded fragment with its type as the `'tui-type` syntax property, and reads it back when it builds larger expressions. Macros do not yet read this property from their source arguments; the syntax classes above are still the way to get an argument's type.

## Running

* `racket examples/basics.rkt` runs the program. The module's `main` submodule assembles it into a temporary exe and runs it.
* Run the module in DrRacket. Each REPL interaction is type checked against the module's functions, compiled into a fresh entry point, assembled with the module's methods, and run. The REPL also accepts function `define`, `using`, `open` and macros. It rejects module value `define`.
* `racket -l- tui/build examples/basics.rkt build/basics.exe` writes a standalone exe.
* `raco test tests/` runs the end-to-end tests.
* `examples/linq.rkt` uses `System.Linq` on lists and stored lambdas. `examples/fnlib.rkt` is a library with the `compose` macro and the `square` identifier macro, which it type checks on its arguments. `examples/phase1.rkt` shows macros that read CLR metadata.

## Layout

| File                | Phase | Role                                                                               |
|---------------------|-------|------------------------------------------------------------------------------------|
| `main.rkt`          | 0, 1  | The language: `#%module-begin`, `#%top-interaction`, and the typed forms            |
| `private/clr.rkt`   | 1     | The .NET view: references, type names, methods, overloads, conversions (Rangi reader) |
| `private/runtime.rkt` | 0   | Turns a Tui program into Rangi ilasm, writes the exe, runs it                        |
| `private/meta-server.rkt` | 0 | Editor helper: JSON lines on stdio. Answers scopes, names, types and members for completion |
| `editors/vscode-tui/` | -   | VS Code companion: completion and Browse Members, through the editor helper. See its README |
| `build.rkt`         | 0     | Command line: compile a Tui module to an exe                                        |
